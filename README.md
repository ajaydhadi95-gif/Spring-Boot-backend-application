# 🚀 App Backend – CI/CD Deployment

A production-style **Spring Boot backend application** demonstrating an automated DevOps CI/CD workflow using **GitHub, Jenkins, Maven, Docker, Docker Hub, Kubernetes, and AWS EKS**.

# ☕ Spring Boot Application

The backend application is developed using **Java and Spring Boot** and is built using Maven.

### Build Application

```bash
./mvnw clean package
```

For Windows:

```powershell
mvnw.cmd clean package
```

The generated JAR file will be available inside:

```text
target/
```

# 🐳 Docker

The Spring Boot application is containerized using Docker.

### Build Docker Image

### Run Container

```bash
docker run -d -p 8080:8080 booking-backend:latest
```

### Check Running Container

```bash

```

# 🔄 Jenkins CI/CD Pipeline

Jenkins automates the complete application deployment workflow.

### Pipeline Stages

```text
GitHub
   ↓
Jenkins
   ↓
Checkout
   ↓
Maven Build
   ↓
Docker Build
   ↓
Docker Tag
   ↓
Docker Hub Login
   ↓
Docker Push
   ↓
AWS EKS
   ↓
Kubernetes Deployment
```

### Jenkins Pipeline Responsibilities

1. Checkout source code from GitHub
2. Build the Spring Boot application using Maven
3. Create the Docker image
4. Generate a versioned Docker image tag
5. Login securely to Docker Hub
6. Push the Docker image to Docker Hub
7. Deploy the application to Kubernetes
8. Update the Kubernetes Deployment
9. Perform a rolling update
10. Verify successful deployment

---

# 🐳 Docker Image Versioning

Jenkins can use `BUILD_NUMBER` to create unique image versions.

For example:

```text
Build #8  → booking-backend:8
Build #9  → booking-backend:9
Build #10 → booking-backend:10
```

The latest image can also be maintained as:

```text
booking-backend:latest
```

This provides traceable application releases and makes rollback easier.

# ☸️ Kubernetes Deployment

The backend application is deployed to **Kubernetes on Amazon EKS**.

The Deployment can run multiple replicas:

```yaml
replicas: 2
```

Running multiple replicas improves application availability.

### Check Pods

```bash
kubectl get pods -o wide
```

### Check Deployment

```bash
kubectl get deployment
```

### Check Services

```bash
kubectl get svc
```

# 🌐 Kubernetes Service

The backend can be exposed using a Kubernetes `LoadBalancer` service.

# 🏗️ Infrastructure as Code – Terraform

AWS infrastructure can be provisioned and managed using **Terraform**.

Terraform enables Infrastructure as Code (IaC), allowing infrastructure to be created consistently through configuration files.

Typical workflow:

```text
Terraform Code
      ↓
terraform init
      ↓
terraform validate
      ↓
terraform plan
      ↓
terraform apply
      ↓
AWS Infrastructure
      ↓
Amazon EKS
```

### Terraform Commands

```bash
terraform init
```

```bash
terraform validate
```

```bash
terraform plan
```

```bash
terraform apply
```

To remove Terraform-managed infrastructure:

```bash
terraform destroy
```

# 🔁 Deployment Strategy

The CI/CD pipeline uses Kubernetes rolling updates to deploy new application versions.

Example:

```text
Version 1
   ↓
Version 2
   ↓
Rolling Update
   ↓
New Pods Created
   ↓
Old Pods Terminated
```

This reduces application downtime during deployments.

---

# ↩️ Rollback

If a deployment has an issue, Kubernetes can rollback to the previous version.

### Check Deployment History

```bash
kubectl rollout history deployment/booking-backend
```

### Rollback

```bash
kubectl rollout undo deployment/booking-backend
```

### Verify Rollout

```bash
kubectl rollout status deployment/booking-backend
```

# 🔐 Docker Hub Authentication

Docker Hub credentials should be stored securely in **Jenkins Credentials**.

Do not hardcode Docker Hub passwords or access tokens inside the Jenkinsfile.

Example Jenkins credential:

```text
dockerhub-credentials
```
